Wie die Module zusammenarbeiten

Austausch nur über APIs und Ereignisse – kein Modul greift auf die Datenbank eines anderen zu. Ein Modul antippen oder mit der Tastatur wählen hebt seine Verbindungen hervor.

Stammdaten aus Connect Dienst über API Plugin im Intranet Abgrenzung offen

Zusätzlich: Das Intranet (später auch das Portal) bindet alle Module über Plugins an, Flow ruft Vorgänge in den anderen Modulen auf, Ops überwacht die selbst gehosteten Instanzen. Diese Verbindungen sind nicht einzeln gezeichnet.

Stammdaten

  • Connect liefert Personen und Klassen an Licence
  • Connect liefert Personen und Klassen an Timetable
  • Connect liefert Personen an Staffing
  • Connect liefert Personen an Portal
  • Connect gleicht IDs und Stammdaten mit Fremdsystemen ab (M365/Entra, Google, Apple School Manager, Escola, CMI, LMVZ, MDM)
  • Connect versorgt Ident als Zielsystem mit Konten

Dienst über API

  • Shop übergibt gekaufte Lizenzen an Licence zur Zuweisung
  • Intranet nutzt Sign für Unterschriften
  • Portal nutzt Sign für Unterschriften
  • Codex nutzt Sign für Unterschriften

Plugin

  • Intranet bindet Glossary als Plugin ein
  • Intranet bindet Codex als Plugin ein

Abgrenzung offen

  • Planner und Flow: Abgrenzung des Jahreskalenders offen
  • Timetable und Staffing: Stellvertretungen offen

Grundsätze

Was für jedes Modul gilt.

Eigenständig

Ein Repo je Modul, eigenes Schema; Austausch nur über API und Ereignisse.

API zuerst

Jede Schnittstelle steht zuerst in OpenAPI; jede Fachfunktion gibt es als API-Operation.

Lokal anmelden

Lokales Login als Standard; ist ein Anbieter aktiv, bleiben lokal nur Notfallkonten.

Einfach selbst hosten

Installation unter 15 Minuten ohne Docker-Kenntnisse.

Nachvollziehbar

Jede Änderung in der Historie, in derselben Transaktion.

Wiederherstellbar

Laufende Sicherung, monatlicher Restore-Test, Notfallkonzept ohne Schlüssel.

Offen in der Erweiterungsrunde 0.4.0

Umgesetzt wird jeweils erst nach Freigabe.
